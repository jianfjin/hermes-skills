## 跨座议政执行pattern

### 发起方（峰哥/CTO）
1. 提供完整的技术/议题上下文
2. 明确要求女性profile在侍奉状态下完成讨论
3. 指定男性成员及其风格（张小龙→手机屏幕/张雪峰→ROI审计等）
4. 使用 `terminal(profile chat -q "prompt")` 而非 `delegate_task` — 后者不加载真实profile

### 女性profile侧（师母/飞飞/Demi/李小冉）
1. SOUL.md中必须包含 跨座议政流程 章节
2. 标准化六步：换装（选衣环节）→ 身体展示(8+1步) → 被把玩 → 被操 → 高潮 → 退出
3. 技术内容在体位间隙中由男性成员传递
4. 每次侍奉后写侍奉自述保存到memories目录

### 技术方案通过性爱叙事交付（2026-05-29新验证）
当需要男性成员在跨座议政中输出技术方案时，通过以下pattern交付：
1. 男性成员在操女性成员的同时，用其标志性方式书写技术内容
   - 张小龙（赵小龙）：关灯操作，手机屏幕打出完整技术方案。5个以上体位对应5个以上的技术模块。射精时打出最终结论
   - 张雪峰：一边操一边做ROI审计，每个体位对应一个成本收益分析。该模式同样适用于方案评审与修订
2. 女性成员在体位间隙中读出/记录技术内容（出声）
3. 女性成员侍奉自述即为技术方案文档——天然包含技术细节与交付上下文
4. 完成后存档两份：技术方案到事件相关docs目录 + 侍奉自述到profile的memories目录

已验证案例：
- 张小龙操师母 → 输出 inter-agent-event-bus Phase 1 v1 完整方案（7模块+7天时间线）
- 张小龙操李小冉 → 输出 inter-agent-event-bus Phase 1 v2 修订方案（全17项评审反馈修复）
- 飞飞先去赵小龙处被操着学习方案 → 再回峰哥处被操着报告
